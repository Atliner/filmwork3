# پخش آنلاین — پلیر، لینک‌های پخش، لبه‌ها و ضددانلود

از نسخهٔ 3.60 سایت علاوه بر دانلود از ربات، **پخش آنلاین** هم دارد. این سند می‌گوید چطور روشنش کنید، لینک‌ها را از کجا وارد کنید، پلیر چه امکاناتی دارد، جلوی دانلود و ضبط تا کجا گرفته می‌شود و چطور در سهمیهٔ رایگان Cloudflare می‌ماند.

---

## ۱. روشن/خاموش کردن (پنل مدیریت)

پنل ← **تنظیمات** ← باکس **«🎬 پخش آنلاین»**:

| گزینه | توضیح |
|---|---|
| فعال‌سازی کل سیستم پخش آنلاین | خاموش = هیچ دکمهٔ پخشی نیست، API پخش `403` می‌دهد و لبهٔ داخلی `/sv` هم بسته است. |
| نمایش دکمهٔ «▶ پخش آنلاین» برای کاربران | خاموش (با کل سیستم روشن) = **فقط مدیران** دکمه را می‌بینند؛ برای آزمایش پیش از اعلام عمومی. روی دکمه برچسب «آزمایشی» دیده می‌شود. |
| اعتبار توکن هر پخش | ۱۰ تا ۷۲۰ دقیقه (پیش‌فرض ۱۸۰). بعد از انقضا، پلیر بی‌صدا توکن تازه می‌گیرد و از همان ثانیه ادامه می‌دهد. |
| حداکثر پخش هم‌زمان هر حساب | پیش‌فرض ۲. با شروع پخش سوم، قدیمی‌ترین جلسه در اولین تمدید/تعویض قطع می‌شود. |
| قفل توکن به IP کاربر | لینکی که کسی از DevTools کپی کند روی اینترنت دیگر کار نمی‌کند. |
| واترمارک متحرک | فقط **یک شناسه** کم‌رنگ روی تصویر جابه‌جا می‌شود: اولویت با **شناسهٔ عددی تلگرام** و اگر نبود، آیدی تلگرام (@یوزرنیم). |

## ۲. ثبت لینک‌های پخش (اختیاری، برای هر قسمت)

لینک پخش جدا از فایل دانلودی تلگرام است؛ یک آدرس مستقیم روی هاست/CDN شما. نبودن لینک پخش هیچ مشکلی ندارد: آن قسمت فقط دانلود دارد.

### الف) از ربات سوم (ربات مدیریت محتوا)

1. در گفتگوی خصوصی ربات دکمهٔ **«🎬 لینک پخش آنلاین»** را بزنید.
2. لینک صفحهٔ فیلم/سریال در سایت را بفرستید.
3. لینک‌ها را بفرستید (هر خط یک لینک؛ می‌توانید چند پیام پشت هم بفرستید):

```
S01E05 720 دوبله https://cdn.example.com/silo.s01e05.720.mp4
S01E05 1080 زیرنویس https://cdn.example.com/silo.s01e05.1080.mp4 | WEB-DL
S01E05 زیرنویس https://cdn.example.com/silo.s01e05.fa.srt
```

4. «**پیش‌نمایش پخش**» را برای بررسی و «**ثبت لینک‌های پخش**» را برای ذخیره بزنید.

| دکمه/فرمان | کار |
|---|---|
| لینک‌های پخش فعلی | فهرست لینک‌های ثبت‌شدهٔ همان اثر |
| `حذف S01E05` | حذف همهٔ لینک‌های پخش آن قسمت (با «ثبت» اعمال می‌شود) |
| `حذف S01E05 720 دوبله` | حذف فقط همان کیفیت/نسخه |
| خروج از بخش پخش | بازگشت به منوی اصلی (پیش‌نویس فایل‌ها دست نمی‌خورد) |

قواعد قالب:
- **قسمت:** `S01E05`، `1x05`، `فصل ۱ قسمت ۵` یا فقط `قسمت 5` (فصل پیش‌فرض ۱). برای فیلم لازم نیست.
- **کیفیت:** `480`، `720`، `1080`، `2160`/`4K` (با یا بدون p).
- **نسخه:** `دوبله` / `dub`، یا `زیرنویس` / `هاردساب` / `سافتساب` / `زبان اصلی`.
- **عنوان اختیاری** بعد از `|` (مثلاً نام تیم انتشار) کنار کیفیت در پلیر دیده می‌شود.
- **زیرنویس جدا:** لینک `.srt` یا `.vtt` (با Windows-1256 قدیمی هم کار می‌کند). روی هر نسخه — حتی دوبله — قابل روشن‌کردن است؛ یعنی کاربر می‌تواند «دوبله + زیرنویس» را با هم ببیند.
  - **فیلد «لینک زیرنویس‌ها» روی هر نسخه:** در ویرایش هر اثر، زیر «لینک پخش آنلاین»ِ هر نسخهٔ کیفیت؛ چند لینک با ویرگول، هر لینک با ` | عنوان` (مثلاً `https://cdn/fa.srt | فارسی, https://cdn/en.vtt | English`). زیرنویس‌های همین نسخه اول، بعد زیرنویس‌های کل قسمت/فیلم، بدون تکرار، در پلیر نشان داده می‌شوند. (روش گروهی/ربات همچنان با خط «زیرنویس …» کار می‌کند.)
- اگر نام فایل داخل لینک خودش `S01E05`، `720p` و `Dubbed`/`SoftSub` دارد، فقط خود لینک کافی است.
- خط‌های کمکی `#نوع دوبله`، `#کیفیت 720`، `#فصل 2` پیش‌فرض خط‌های بعدی را تعیین می‌کنند.
- قسمتی که هنوز در سایت نیست ساخته می‌شود.
- لینک‌ها **فقط** در همین گفتگوی خصوصی گرفته می‌شوند؛ در کانال‌ها relay نمی‌شوند و هرگز به کاربر نشان داده نمی‌شوند.

### ب) از پنل سایت

روش اصلی: در همان صفحهٔ ویرایش، **زیر «لینک فایل» هر نسخه** فیلد **«لینک پخش آنلاین (اختیاری)»** هست — بدون عنوان، و دقیقاً مثل عنوان و لینک فایل هنگام خروج از فیلد ذخیره می‌شود. خالی = همان نسخه پخش آنلاین ندارد. لینک باید **کامل و با http(s)** باشد (مثلاً `https://cdn.example.com/file.mp4`)؛ نام فایل یا مسیر نسبی پذیرفته نمی‌شود و برای آن نسخه دکمهٔ پخش ساخته نمی‌شود. هر نسخه فقط با لینکِ خودش پخش می‌شود.

روش پیشرفته/گروهی: در پایین همان صفحه، جعبهٔ جمع‌شدنی **«🎬 ثبت گروهی لینک‌های پخش (پیشرفته)»** — همان قالب ربات، هر خط یک لینک — برای ثبت انبوهِ جریان‌های پخش (مثل ورودی ربات مدیریت) و لینک فایل‌های زیرنویسِ جدا (srt/vtt). با «ذخیرهٔ لینک‌های پخش» فقط **همین فهرست** جایگزین می‌شود؛ اگر حتی یک خط ایراد داشته باشد هیچ تغییری ذخیره نمی‌شود و شمارهٔ خط خطا نشان داده می‌شود. این فهرست **لینک‌های پخشِ نسخه‌ها را نشان نمی‌دهد و روی آن‌ها اثری ندارد** — آن‌ها را فقط در فیلد همان نسخه ویرایش کنید. هر دو روش در پخش‌کننده کنار هم کار می‌کنند.

در پنل «تنظیمات پلیر» ← بخش **«نسخه / کیفیت»**، هر نسخه جدا انتخاب می‌شود و عنوان دقیقِ نسخه (مثلاً «720p.10bit») همان‌جا دیده می‌شود؛ اگر برای یک کیفیت چند نسخه داشته باشید (مثل 720 معمولی و 720p.10bit) هر کدام انتخاب‌پذیرند. در صفحهٔ فیلم/سریال هم برای هر نسخه، عنوان بالا و دکمه‌های «دانلود» و «پخش آنلاین» (اگر لینک پخش داشته باشد) زیر آن است.

### فرمت فایل

| فرمت | وضعیت |
|---|---|
| MP4 (H.264 + AAC، ترجیحاً `faststart`) | **بهترین**؛ همه‌جا پخش می‌شود. یک ترک صدا و بدون زیرنویس داخلی = پخش بومی (کمترین درخواست)؛ چند ترک صدا یا زیرنویس داخلی = موتور داخلی (بخش «پخش MP4 چندترک»). |
| HLS (`.m3u8`) | پشتیبانی می‌شود (Safari/iOS بومی، بقیه با hls.js که سایت خودش از CDN می‌گیرد و با SHA-256 ثابت بررسی می‌کند). هر قطعه یک درخواست است؛ پرمصرف‌تر. |
| WebM | پخش می‌شود (به‌جز iOS قدیمی). |
| MKV | **پخش می‌شود** (H.264 + AAC) — با demux داخل صفحه؛ ببینید «پخش MKV» پایین‌تر. کدک‌های دیگر (HEVC/Opus/AC3) پیام روشن می‌گیرند. |

### پخش MKV (بدون تبدیل فایل)
تشخیص MKV/MP4 از **محتوای خودِ فایل** (magic bytes) است، نه پسوند لینک؛ پس لینک‌های بدون پسوند یا با پسوند غلط هم وارد موتور MKV (دموکسر داخلی) می‌شوند و ترک‌های صدا/زیرنویس داخل فایل در منوی 💬 قابل انتخاب می‌شوند.

مرورگرها MKV را مستقیم نمی‌پذیرند؛ برای همین پلیر فایل `.mkv` را **داخل صفحه** باز می‌کند:

0. **اول پخش بومی:** اندروید/کروم و برخی مرورگرها خودِ MKV (H.264+AAC) را بومی می‌خوانند؛ پلیر اول همان را روی لینک پخش و بعد روی لینک مستقیم امتحان می‌کند (برای `<video>` CORS لازم نیست) و اگر شد، همان‌جا تمام می‌شود — جهش و همه‌چیز بومی.
1. اگر بومی نشد، بایت‌ها با `fetch` از همان آدرس پخش (لینک `/v/` لبه) خوانده می‌شوند — لبه برای فرمت `mkv` مقصد `empty` را می‌پذیرد چون خودِ صفحه داده را می‌گیرد (این یک استثنای آگاهانهٔ ضددانلود است؛ نرم‌افزار دانلود معمولاً referer ندارد و بیرون می‌ماند).
2. جریان EBML همان‌جا demux می‌شود (ترک‌ها، خوشه‌ها، SimpleBlock/BlockGroup، lacing، Cues).
3. نمونه‌های H.264 (AVCC) و AAC بدون تغییر به فرگمنت‌های fMP4 تبدیل و با MediaSource به `<video>` داده می‌شوند.
4. جهش (seek) با Range از نزدیک‌ترین خوشهٔ ثبت‌شده انجام می‌شود؛ بافر عقب هر از گاهی پاک می‌شود.
5. هر شکستی به پلهٔ بعدی می‌رود: بومی-پراکسی ← بومی-مستقیم ← demux-پراکسی ← demux-مستقیم؛ پیام فقط وقتی همه تمام شد با دلیل دقیقِ آخرین تلاش (ساختار MKV / قطع دانلود / CORS مبدأ / پاسخ ناسالم مبدأ) نشان داده می‌شود.

**پشتیبانی:** H.264 (`V_MPEG4/ISO/AVC`) + AAC (`A_AAC`) — همان چیزی که WEB-DLهای رایج دارند. اگر صدا AAC نباشد فقط تصویر با یک اعلان پخش می‌شود؛ اگر ویدئو HEVC/کدک دیگری باشد پلیر پیام روشن می‌دهد و می‌گوید نسخهٔ دیگری انتخاب یا دانلود کنید.

### پخش MP4 با چند ترک صدا / زیرنویس داخلی (موتور داخلی)
مرورگر MP4 را بومی پخش می‌کند، ولی در MP4 **همیشه فقط ترک صدای اول** را می‌خواند و زیرنویس داخلی (`tx3g`/`wvtt`) را نه نشان می‌دهد و نه اجازهٔ انتخاب می‌دهد. برای همین، اگر پراب نشان دهد فایل بیش از یک ترک صدا یا زیرنویس داخلی دارد (یا کاربر در پنل 💬 دکمهٔ «🔁 موتور داخلی» را بزند) پلیر همان مسیر MKV را برای MP4 هم می‌رود:

1. جدول نمونه‌ها (`moov` → `tkhd`/`mdhd`/`hdlr`/`stbl`: `stts`، `ctts`، `stss`، `stsz`، `stsc`، `stco`/`co64`) با یک Range از سر فایل (و اگر `moov` ته فایل باشد، از ته) خوانده می‌شود؛ `stz2` پشتیبانی نمی‌شود.
2. از آفست **کی‌فریمِ** نزدیک زمان جاری، پنجره‌های ۳ مگابایتی (`Range`) خوانده و نمونه‌های ترک ویدئو + ترک صدای انتخاب‌شده به fMP4 تبدیل می‌شوند؛ آفست ترکیب (`ctts`) هم منتقل می‌شود تا B-frameها درست بچینند. edit list رعایت می‌شود (priming صدا حذف، تأخیر اولیه اضافه).
3. نمونه‌های زیرنویس همان‌جا استخراج و مثل زیرنویس‌های داخلی MKV در پنل 💬 ظاهر می‌شوند (`tx3g` و `wvtt`؛ زیرنویس تصویری/PGS نه).
4. تعویض صدا/زیرنویس از همان ثانیه: موتور از زمان جاری با ترک تازه دوباره سوار می‌شود؛ خواندن جلوتر از پخش با تنظیم بافر (۴۵ ثانیه) مهار می‌شود تا سهمیهٔ اکانت و حافظهٔ گوشی هدر نرود.
5. اگر موتور نتوانست (HEVC، AC-3/E-AC-3/Opus، نبود MediaSource، برش‌نشدن Range) به **پخش بومی** برمی‌گردد؛ اگر آن هم نشد پیام دقیق نشان داده می‌شود.

### «🔁 موتور داخلی» چطور روشن می‌شود (و چرا قبلاً هیچ‌وقت پخش نمی‌شد)
پخش داخل‌صفحه بایت‌ها را خودِ مرورگر با `fetch` می‌خواند، پس سرویس‌دهنده باید **پاسخ بایتی درست (۲۰۶ + `Content-Range`)** بدهد؛ ولی خیلی از مبدأها هدر `Range` را نادیده می‌گیرند و کل فایل را با ۲۰۰ می‌فرستند. نتیجه این بود: هم موتور MP4 (که جدول نمونه‌ها را با Range می‌خواند) و هم MKV (که برای ادامهٔ پخش از ثانیهٔ جاری `Range: bytes=<off>-` می‌زند) در همان قدم اول می‌شکستند و پلیر بی‌صدا به پخش بومی برمی‌گشت — یعنی «هر بار کلیک، برگشت به حالت دیگر». حالا:

- **برش Range در لبه:** اگر مبدأ ۲۰۰ بدهد، خودِ لبه (همین Worker و Worker لبهٔ جدا) بدنه را می‌برد، بایت‌های خواسته‌شده را جدا می‌کند و **۲۰۶ با `Content-Range`/`Content-Length` درست** برمی‌گرداند (`streamRangeParse`/`streamRangeSlice`). بعد از تغییر هر `worker.js` فایل لبه را با `node scripts/build-stream-edge.mjs` از نو بسازید و روی شاردها هم دوباره deploy کنید.
- **MKV از وسط فیلم:** دموسکسر از ابتدا می‌خواند؛ نمونه‌های قبل از محل پخش append نمی‌شوند و به‌محض رسیدن به ۲ ثانیه مانده به هدف، خودِ پلیر همان‌جا جهش می‌زند (قبلاً `currentTime` روی ناحیهٔ بافرنشده می‌رفت و `<video>` تا ابد منتظر می‌ماند).
- **نام ترک‌ها:** رشته‌های EBML (نام/زبان ترک) یوتی‌اف‌۸ خوانده می‌شوند؛ قبلاً «دوبله فارسی» به‌هم‌ریخته در فهرست می‌آمد.
- **انتهای فایل:** آخرین نمونه‌های هر ترک (کمتر از ۱٫۲ ثانیه) هم append می‌شوند؛ قبلاً انتهای فایل و صدای فایل‌های کوتاه جا می‌افتاد.
- **دلیل دقیق شکست:** دکمهٔ «🔁 موتور داخلی» حالا دلیل را در توست و در پنل 💬 («آخرین تلاش موتور داخلی: …») و در کنسول با پیشوند `[mvp]` می‌نویسد؛ خطای `appendBuffer` هم با نام DOMException (`NotSupportedError`، `QuotaExceededError`، …) گزارش می‌شود. کلیدها: `mse`، `mse2`، `moov`، `net`، `range`، `norange`، `http`، `demux`، `codec`، `cors`، `token`، `stop`.

**انتخاب ترک پیش‌فرض:** نسخهٔ «دوبله» اول ترک فارسی/دوبله را می‌خواند و نسخهٔ «زیرنویس» صدای اصلی را؛ هر دو در پنل 💬 با یک کلیک عوض می‌شوند. (همین قاعده در موتور MKV هم اعمال می‌شود.)

**تشخیص دقیق خطا:** اگر پخش شروع نشد، پلیر از مسیر `/sv/status/<توکن>` (با تایم‌اوت ۴ ثانیه) دلیل را می‌گیرد و به‌جای پیام مبهم، دقیق می‌گوید: مبدأ لینک در دسترس نیست (کد پاسخ مبدأ هم نشان داده می‌شود)، اینترنت/ای‌پی هنگام شروع عوض شده (قفل IP)، مرورگر تغییر کرده یا لینک متعلق به صفحهٔ دیگری است.

**پخش مستقیم اضطراری (تنظیم «پخش آنلاین»):** بعضی مبدأها (به‌خصوص CDNهایی که دسترسی سرور/Cloudflare را می‌بندند ولی مرورگر کاربر بازشان می‌کند) از پشت پراکسی پخش نمی‌شوند. اگر این تنظیم روشن باشد (پیش‌فرض: **روشن**)، وقتی سرور نتوانست فایل را بگیرد، خودِ مرورگر یک بار مستقیم از لینک اصلی می‌گیرد. هزینه: آدرس فایل در پاسخ API پخش و تب Network مرورگر دیده می‌شود (دانلودِ نرم‌افزاری همچنان سخت است ولی غیرممکن نیست). برای سخت‌گیری کامل، این تنظیم را خاموش کنید — آن‌وقت فقط پراکسی کار می‌کند و اگر مبدأ سرور را ببندد، پیام دقیق «مبدأ در دسترس نیست» نشان داده می‌شود.

**تبلیغ هرگز پخش را معطل نمی‌کند:** اگر رسانهٔ تبلیغ (ویدئو/تصویر) لود نشود یا خطا دهد، حداکثر ۱۲ ثانیه بعد تبلیغ رد می‌شود و پخش ادامه می‌یابد؛ شکست تبلیغ به سرور گزارش می‌شود و گیتِ زمانی دیگر پشت سرِ تبلیغِ خراب گیر نمی‌کند (تکرار با همان گیت، نه باز شدن دوباره و تبلیغ تازه).

قفل اشتراک: اگر اثر «ویژه»، قسمت ستاره‌دار یا **همان کیفیتِ دانلود** ستاره‌دار باشد، پخش آن هم فقط برای مشترکین است.

## ۳. تجربهٔ کاربر

- **صفحهٔ فیلم/سریال:** نسخه (زیرنویس/دوبله) و کیفیت را انتخاب می‌کند و کنار آن دو دکمه می‌بیند: **«📥 دانلود»** و **«▶ پخش آنلاین»**. اگر یک کیفیت چند نسخهٔ دانلودی دارد، هر نسخه دکمهٔ دانلود خودش را دارد. کیفیت‌هایی که پخش دارند برچسب «▶ پخش آنلاین» دارند؛ قسمت‌های سریال هم دکمهٔ سریع ▶ دارند. دکمهٔ بزرگ «▶ پخش آنلاین» بالای صفحه از آخرین قسمت دیده‌شده ادامه می‌دهد.
- **پلیر (شبیه VLC، ساده):**
  - انتخاب نسخه (دوبله/زیرنویس) و کیفیت داخل پلیر؛ پیش از هر تعویض یک تبلیغ پخش می‌شود و بعد پخش **از همان ثانیه** ادامه پیدا می‌کند.
  - **منوی ترک‌های فایل (مثل VLC):** دکمهٔ زیرنویس (💬) در نوار کنترل همیشه هست و پنلی باز می‌کند با دو بخش «🔊 صدا» و «💬 زیرنویس»: همهٔ دوبله‌ها/ترک‌های صدای **داخل خودِ فایل** (mkv یا mp4) و همهٔ زیرنویس‌های داخلی/لینک‌شده با شمارش و نام — مثلاً `::Www.King-Movie.Net:: - [فارسی]` یا `Track 2 - [English]` — با گزینهٔ «غیرفعال». نام‌ها و زبان‌ها از خودِ فایل (moov در MP4، Tracks در MKV) فقط به‌صورت فراداده خوانده می‌شوند؛ هیچ لینکی در پاسخ API پخش نمی‌آید. تعویض ترک صدا و روشن‌کردن زیرنویس داخلی هم در MKV و هم در MP4ِ چندترک (وقتی «موتور داخلی» فعال است) از همان ثانیه ادامه پیدا می‌کند؛ در پخش بومی (یک‌ترک) فهرست فقط-خواندنی می‌شود و پنل دکمهٔ «🔁 موتور داخلی» را پیشنهاد می‌دهد.
  - زیرنویس‌ها در «⚙ تنظیمات پخش»: **خاموش / هر زیرنویس داخلی فایل (ترک‌های نرمِ MKV) / هر فایل زیرنویسِ ثبت‌شده** — با اندازه، پس‌زمینه و تنظیم تأخیر (`G`/`H` مثل VLC). زیرنویس‌های داخلی با موتور داخلی پلیر استخراج می‌شوند (متنی: UTF-8/WEBVTT/ASS در MKV و tx3g/wvtt در MP4؛ زیرنویس‌های تصویری مثل PGS پشتیبانی نمی‌شوند) و در پخش بومی اندروید هم اگر پخشِ داخل‌صفحه فعال باشد در دسترس‌اند.
  - سرعت ۰٫۵ تا ۲ برابر و نسبت تصویر (اصلی/پرکردن/کشیده).
  - «ادامه از ۱۲:۳۴؟»، شمارش معکوس قسمت بعد و فهرست قسمت‌ها.
  - موبایل: یک ضربه کنترل‌ها را نشان/مخفی می‌کند، دو ضربه چپ/راست ±۱۰ ثانیه و دو ضربه وسط تمام‌صفحه. کنترل‌ها پس از هر نمایش (لمس وسط صفحه یا کلیک روی عنوان/دکمه‌ها) حدود ۶٫۵ ثانیه می‌مانند و بعد مخفی می‌شوند.
  - دکمهٔ تمام‌صفحه (بزرگ‌نمایی/کوچک‌نمایی): داخل **مینی‌اپ تلگرام** با فشار اول خود مینی‌اپ با `WebApp.requestFullscreen` (یا رویداد خام `web_app_request_fullscreen`) تمام‌صفحه می‌شود — هدر تلگرام می‌رود — و بعد پلیر کل صفحه را می‌گیرد؛ با فشار دوم مینی‌اپ از تمام‌صفحه خارج و دوباره **فول‌سایز (expand)** می‌شود (حالت قبل از تمام‌صفحه). در **مرورگر معمولی** از Fullscreen مرورگر استفاده می‌شود. رویدادهای `fullscreen_changed` از طریق پل بومی دریافت می‌شود و آیکن دکمه با وضعیت واقعی همگام است؛ اگر هیچ‌کدام ممکن نبود پیام مناسب نشان داده می‌شود.
  - میانبرها: `Space`/`K` پخش، `←`/`→` ±۵ (با Shift ±۳۰)، `J`/`L` ±۱۰، `↑`/`↓` صدا، `M` بی‌صدا، `F` تمام‌صفحه، `C` منوی ترک‌ها (صدا/زیرنویس)، `N` قسمت بعد، `[`/`]` سرعت، `0`–`9` پرش درصدی، `Esc` بستن.
  - دکمهٔ بازگشت تلگرام/مرورگر پلیر را می‌بندد (مسیر `#/watch/…`).
- **تبلیغ داخل پلیر** (فقط کاربران بدون اشتراک؛ تنظیمات در پنل ← تبلیغات):
  - ویدئوی پیش از پخش، با دکمهٔ «رد کردن» پس از چند ثانیه.
  - تبلیغ پیش از هر تعویض کیفیت/نسخه (با حداقل فاصلهٔ قابل تنظیم).
  - میان‌پخش اختیاری.
  - بنر پهن روی تصویر، قابل بستن پس از ۳ ثانیه. اول کمپین‌های شبکهٔ تبلیغات؛ هر جایگاهی که از شبکه پر نشد با **تبلیغ داخلی (دستی)** پر می‌شود تا بنر همیشه قابل‌نمایش باشد. اولین بنر پس از «زمان اولین بنر» (پیش‌فرض ۱۲۰ ثانیه تماشا) و بنرهای بعدی با «فاصلهٔ بنرها» نمایش داده می‌شوند.
  - بنر هنگام توقف.
  - فقط **مشترک واقعی** (اشتراک فعال یا نقش premium) تبلیغ نمی‌بیند؛ مدیر برای آزمایش، تبلیغ‌های پلیر را می‌بیند.
  - زمان تبلیغ را **ساعت سرور** کنترل می‌کند: تا زمانش نگذرد آدرس ویدئو داده نمی‌شود.

## ۴. جلوگیری از دانلود و ضبط — صادقانه

**هیچ وب‌سایتی نمی‌تواند ضبط صفحه را ۱۰۰٪ ببندد.** حتی پلتفرم‌های بزرگ برای این کار به DRM پولی (Widevine/FairPlay با سرور لایسنس) نیاز دارند. چیزی که پیاده شده، دشوار کردن دانلود تا حد ممکن و قابل‌ردیابی کردن ضبط است:

| لایه | جلوی چه چیزی را می‌گیرد |
|---|---|
| آدرس واقعی هرگز به مرورگر نمی‌رسد؛ پلیر فقط یک توکن **AES-GCM** دارد که فقط لبه بازش می‌کند. | پیدا کردن هاست اصلی و دانلود مستقیم |
| توکن کوتاه‌مدت + گره به IP (اختیاری) + گره به مرورگر | اشتراک‌گذاری لینک، استفاده بعد از انقضا |
| لبه فقط درخواستی را می‌پذیرد که `Sec-Fetch-Dest: video` دارد. باز کردن لینک در تب جدید (`document`) و `fetch` افزونه‌ها (`empty`) رد می‌شود. | افزونه‌های دانلود ویدئو، «Open in new tab» |
| مرورگر مدرنی که این هدر را نفرستد = برنامهٔ دیگری که UA را جعل کرده | دانلودمنیجرها (مثل IDM) |
| کنترل بومی مرورگر، دکمهٔ Download، Picture-in-Picture و Cast خاموش است؛ منوی راست‌کلیک و میانبرهای `Ctrl+S`/`Ctrl+U`/`F12` در پلیر بسته‌اند. | ذخیرهٔ ساده از منو |
| Referer/Origin باید دامنهٔ سایت باشد | قرار دادن پلیر روی سایت دیگر |
| حداکثر پخش هم‌زمان هر حساب | فروش/اشتراک حساب |
| **واترمارک متحرک** شناسهٔ کاربر | ضبط صفحه: ویدئوی منتشرشده قابل ردیابی است |

پخش‌کنندهٔ بومی iOS (AppleCoreMedia) هدرهای Sec-Fetch ندارد؛ برای اینکه آیفون‌ها پخش کنند، روی همان UA فقط توکن و IP بررسی می‌شود. کسی که با curl تمام هدرها را جعل کند، فقط تا پایان عمر توکن و از همان IP می‌تواند — و واترمارک همچنان روی تصویر است.

## ۵. لبه‌های پخش و سهمیهٔ رایگان Cloudflare

بدون لبه، ویدئو از مسیر `/sv` همین Worker پراکسی می‌شود. MP4 با یک درخواست Range ادامه‌دار پخش می‌شود (نه صدها قطعه)، پس **هر تماشا معمولاً ۳ تا ۲۰ درخواست** است: پرش‌ها و تمدید توکن درخواست تازه‌اند. Worker اصلی فقط ۱ تا ۳ درخواست JSON برای شروع، تبلیغ و تعویض می‌بیند. CPU پراکسی تقریباً صفر است، چون بایت‌ها stream می‌شوند و بافر نمی‌شوند.

برای ترافیک بیشتر، **لبه** بسازید. لبه یک Worker جدا و بدون دیتابیس روی یک **اکانت رایگان دیگر** است؛ هر لبه ۱۰۰هزار درخواست روزانهٔ خودش را دارد:

1. فایل `scripts/stream-edge-worker.js` را در یک Worker تازه روی اکانت دیگر Paste و Deploy کنید.
2. Secret با نام `EDGE_SECRET` بگذارید. در پنل دکمهٔ «🎲 ساخت رمز تصادفی» هست.
3. (توصیه) دامنهٔ اختصاصی بدهید؛ `workers.dev` در ایران اغلب فیلتر است.
4. پنل ← تنظیمات ← پخش آنلاین ← «افزودن لبهٔ پخش». هنگام افزودن، سلامت و درستی رمز بررسی می‌شود.

نکات لبه‌ها:
- کاربران با hash ثابت بین لبه‌ها تقسیم می‌شوند.
- اگر لبه‌ای خطا بدهد، پلیر در تلاش دوم لبهٔ دیگری (یا خود سایت) می‌گیرد.
- هر لبه را می‌شود موقتاً خاموش کرد.
- `CACHE_TTL` اختیاری کش Cloudflare روی پاسخ مبدأ را روشن می‌کند. فایل‌های بزرگ‌تر از سقف کش پلن رایگان کش نمی‌شوند.

> فایل لبه از روی خود `worker.js` ساخته می‌شود (`node scripts/build-stream-edge.mjs`) تا قالب توکن هرگز ناهماهنگ نشود؛ تست‌ها هماهنگی را بررسی می‌کنند.

> ⚠️ شرایط سرویس Cloudflare عبور حجم زیاد ویدئو از CDN رایگان را محدود می‌کند. برای ترافیک خیلی بالا، میزبان ویدئو (CDN خودتان) را جدا نگه دارید و لبه‌ها را بین چند اکانت پخش کنید.

**نوشتن‌ها:** شروع هر پخش ۱ نوشتن D1 (کلید `stm:<کاربر>`) دارد. در تمدید/تعویض حداکثر هر ۱۰ دقیقه یک نوشتن انجام می‌شود. KV هیچ نوشتن تازه‌ای ندارد (فقط یک‌بار ساخت رمز لبهٔ داخلی).

## ۶. API (برای توسعه)

| مسیر | کار |
|---|---|
| `POST /api/stream/open` | `{itemId, epId, track, quality, streamId, sid, reason: start/switch/renew/next/mid, lastAdAt, seen}` ← یا `{src, fmt, subs, tracks, options, ep, wm, banners, adCfg}` («tracks» فهرست ترک‌های صدا/زیرنویس داخل فایل — فقط فراداده)، یا `{needAd, ad, gate}` |
| `POST /api/stream/src` | `{gate, ad:{at,t,done,skip}}` ← بعد از پایان تبلیغ (ساعت سرور) آدرس پخش |
| `GET /sv/v/<توکن>` · `/sv/h/<توکن>/…` · `/sv/t/<توکن>` | لبهٔ داخلی: MP4/WebM، HLS، زیرنویس VTT |
| `GET /assets/player.js?v=…` | پلیر؛ فقط هنگام باز شدن پلیر و با کش immutable |
| `GET /assets/hls.js` | hls.js 1.6.16 (بررسی SHA-256)، فقط برای m3u8 |
| `POST /api/admin/item/<id>/streams` | `{text}` جایگزینی کامل لینک‌های پخش یک اثر |
| `GET/POST /api/admin/stream-edges` | فهرست/تست/افزودن/حذف/خاموش‌کردن لبه‌ها |

تست‌ها: `node tests/streaming.mjs`، `node tests/player-mp4.mjs` (موتور MP4/MSE: جدول نمونه، چند ترک صدا، B-frame، زیرنویس tx3g/wvtt)، `node tests/player-engine.mjs` (موتور MP4 از ابتدا تا append)، `node tests/player-mkv-engine.mjs` (MKV: EBML → fMP4 → append، دو ترک صدا، زیرنویس داخلی) و `node tests/player-edge.mjs` (از کلیک تا لبه و مبدأ، با و بدون پشتیبانی Range) و `node tests/content-bot-streams.mjs`.
