# ساخت EDITOR بدون نوشتن فرمان‌های Cloudflare

`EDITOR` حافظه گفتگو و صف ربات است. لازم نیست آن را دستی در Durable Objects بسازید؛ نصب‌کننده این پروژه ثبت کلاس و اتصال آن را انجام می‌دهد.

## روش ویندوز — پنج قدم

1. **Node.js نسخه LTS، حداقل ۲۲** را از https://nodejs.org نصب کنید. اگر از قبل نسخه مناسب دارید، این قدم لازم نیست.
2. کل پروژه را از GitHub با **Code → Download ZIP** بگیرید و **Extract** کنید. نسخه‌ای را بگیرید که فایل `INSTALL-EDITOR.cmd` دارد. فقط خود فایل cmd را جدا دانلود نکنید؛ پوشه `scripts` و `worker.js` هم لازم‌اند.
3. روی **`INSTALL-EDITOR.cmd` دوبارکلیک** کنید. اگر ویندوز درباره فایل دانلودشده هشدار داد، ابتدا منبع و محتوای فایل را بررسی کنید؛ تنظیمات امنیتی ویندوز را خاموش نکنید.
4. نام Worker را بپرسد: اگر Worker سایت شما `film` است، **Enter** بزنید. مرورگر برای ورود رسمی Cloudflare باز می‌شود؛ با حسابی که سایت داخل آن است وارد شوید و اجازه دسترسی بدهید. اگر چند حساب دارید، حساب سایت را انتخاب کنید.
5. نصب‌کننده نام Worker و کاری را که می‌خواهد انجام دهد نشان می‌دهد. برای تأیید انتشار، نام Worker را دوباره بنویسید؛ مثلاً `film`، و Enter بزنید. Enter خالی یعنی انصراف.

وقتی پیام **«EDITOR ساخته/متصل و بررسی شد»** آمد، به تنظیمات سایت برگردید، صفحه را تازه کنید و **«اتصال ربات به سایت»** را بزنید.

**توکن BotFather، رمز تلگرام یا API Token کلودفلر را داخل این فایل یا چت وارد نکنید.** نصب‌کننده از ورود رسمی مرورگری Wrangler استفاده می‌کند. اجازه دسترسی در صفحه Cloudflare لازم است؛ نصب‌کننده بدون اجازه نمی‌تواند منابع حساب را بسازد.

## دقیقاً چه چیزی خودکار می‌شود؟

- Worker موجود، KV، اتصال‌ها و وضعیت فعلی حافظه بررسی می‌شوند.
- اگر `EDITOR` از قبل درست باشد، فقط پیام آماده‌بودن می‌دهد و دوباره منتشر نمی‌کند.
- اگر کلاس وجود داشته ولی binding نباشد، همان حافظه موجود متصل می‌شود.
- اگر کلاس وجود نداشته باشد، مرحله ساخت SQLite برای `EditorSession` و binding با نام `EDITOR` آماده می‌شود.
- پس از تأیید شما، **فایل `worker.js` همین پوشه روی Worker انتخاب‌شده منتشر می‌شود**. این کار فقط تغییر یک Variable نیست؛ نسخه سایت هم همان نسخه داخل پوشه می‌شود. اگر کد جدیدتری در داشبورد دارید، ابتدا اختلاف آن را بررسی/پشتیبان‌گیری کنید.
- KV و اتصال‌های قبلی با قابلیت `inherit` خود Cloudflare حفظ می‌شوند. مقادیر Variables و Secrets در فایل تنظیمات جدید نوشته یا در خروجی نصب‌کننده چاپ نمی‌شوند.
- تاریخچه migration از سرویس خوانده می‌شود؛ migration قبلی حذف نمی‌شود. هیچ KV namespace جدیدی ساخته و هیچ داده KV حذف نمی‌شود.
- اگر نام `EDITOR` به منبع دیگری تعلق داشته باشد، کلاس‌های Durable Object دیگری روی همان Worker وجود داشته باشند، یا وضعیت نامشخص باشد، نصب متوقف می‌شود؛ چیزی را با حدس جایگزین نمی‌کند.
- قبل از انتشار، تنظیمات دوباره خوانده می‌شوند؛ اگر تغییر کرده باشند نصب متوقف می‌شود. همزمان با نصب، از داشبورد یا ابزار دیگری Deploy نکنید. این بررسی قفل تراکنشی روی تمام استقرارهای حساب نیست.

این برنامه تنظیم توکن ربات، عضویت کانال و webhook را انجام نمی‌دهد. آن تنظیمات قبلی را حفظ می‌کند و فقط مرحله فنی EDITOR/انتشار را ساده می‌کند. migration برگشت‌پذیر خودکار نیست؛ برنامه rollback یا حذف حافظه انجام نمی‌دهد.

## اگر خطا دیدید

- **Node.js نصب نیست:** Node.js LTS را نصب و دوباره فایل را باز کنید.
- **ورود انجام نشد:** مرورگر و اینترنت را بررسی کنید و حساب صحیح Cloudflare را انتخاب کنید. پنجره ورود مرورگر باید روی همان کامپیوتر نصب‌کننده باز شود.
- **Worker پیدا نشد / HTTP 404:** نام Worker را وارد کنید، نه دامنه؛ مثلاً `film` نه `https://film.example.workers.dev`.
- **HTTP 401 یا 403:** حساب انتخابی مجوز مدیریت Worker را ندارد یا ورود منقضی شده؛ دوباره با حساب مجاز وارد شوید.
- **KV پیدا نشد:** نصب روی Worker بدون دیتابیس متوقف شده است. Worker سایت اصلی را انتخاب کنید، نه یک Worker تازه‌ساخته.
- **تنظیمات در حین نصب تغییر کرد:** هیچ انتشار جدیدی انجام نشده؛ پس از پایان استقرار دیگر، دوباره اجرا کنید.
- **ارتباط پس از انتشار قطع شد:** نتیجه ممکن است نامشخص باشد. دوباره اجرا کنید؛ وضعیت موجود بررسی می‌شود و اگر حافظه ساخته شده باشد دوباره ساخته نمی‌شود. نصب‌کننده برای رفع خطا، داده یا migration را پاک نمی‌کند.

فقط متن عمومی خطا یا تصویری بدون رمز و توکن را برای پشتیبانی بفرستید.

## مک/لینوکس یا اجرای دستی

از پوشه اصلی پروژه، با Node.js حداقل ۲۲:

```sh
node scripts/editor-installer.mjs
```

نسخه ابزار Wrangler ثابت است؛ در اولین اجرا با npm دریافت می‌شود. ابزار به اینترنت، دسترسی به npm و Cloudflare و تأیید ورود در مرورگر نیاز دارد. حساب می‌تواند نیازمند فعال‌بودن سرویس Durable Objects و سهمیه کافی باشد.

## نکات امنیتی و آزمون

Wrangler مجوز ورود را در محل استاندارد خودش روی کامپیوتر شما نگه می‌دارد. خروجی فرمان دریافت مجوز توسط نصب‌کننده ضبط می‌شود، نه نمایش. لاگ موقت ابزار خارج از پروژه در پوشه خصوصی ساخته و هنگام پایان برنامه پاک می‌شود؛ بستن اجباری پردازش می‌تواند این پاک‌سازی را ناتمام بگذارد. برای پایان دسترسی محلی، بعداً می‌توانید از خروج رسمی Wrangler استفاده کنید.

نصب‌کننده با API ساختگی آزمایش شده؛ **روی حساب واقعی شما اجرا نشده است**. تست آن هیچ توکن واقعی مصرف نمی‌کند و استقرار انجام نمی‌دهد:

```sh
node tests/editor-installer.mjs
```

مراجع فنی برای نگهدارنده: Cloudflare Workers Script Upload API، multipart upload metadata، Durable Objects migrations و دستورهای `wrangler login` / `wrangler auth token --json`.
