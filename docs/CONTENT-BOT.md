# ربات سوم مدیریت محتوا

## قابلیت این نسخه

این ربات مستقل برای **اثر موجود در سایت** است. مدیر لینک صفحه اثر را می‌فرستد، ربات عنوان/سال/خلاصه را از همان سایت می‌خواند و سپس چهار دسته فایل را دریافت می‌کند: دوبله، هاردساب، سافت‌ساب و زبان اصلی. هر دسته با `/next` قابل ردکردن است. فایل‌ها ابتدا پیش‌نویس هستند و فقط پس از `/review` و `/confirm` منتشر می‌شوند.

- مثال نام قابل تشخیص: `Silo.S02E03.1080p.mkv` یا `Silo.2x03.720p.mkv`.
- کیفیت‌های 480، 720، 1080 و 2160/4K؛ فصل و قسمت از نام فایل، نه حدس ثابت فصل ۱.
- نام نامشخص/نام متفاوت، چندقسمتی بودن فایل یا نبود کیفیت، به تعیین تکلیف مدیر نیاز دارد.
- نام اثر انتخاب‌شده ملاک مقصد است. ربات خودسرانه اثر جدیدی نمی‌سازد و نام فایل به‌تنهایی مجوز تغییر مقصد نیست.
- امکان ارسال فایل، فوروارد فایل از کانال یا لینک `https://t.me/c/.../...`. لینک تنها، نام فایل ندارد و معمولاً به `/assign` نیاز دارد.
- عنوان نسخه را در کپشن فایل بنویسید. نوع دوبله/زیرنویس از مرحله فعلی مشخص می‌شود، نه از حدس نام فایل.
- هر پیش‌نویس حداکثر ۲۰ فایل؛ بعد از ثبت، لینک همان اثر را دوباره بفرستید و دسته بعدی را اضافه کنید.
- فایل‌ها با `copyMessage` در مخزن فعلی کپی می‌شوند؛ Worker فایل‌های چندگیگابایتی را دانلود نمی‌کند و `file_id` یک ربات را به ربات دیگر نمی‌دهد.
- فایل‌های منتشرشده توسط ربات ارسال فعلی سایت از آدرس پیام مخزن دریافت می‌شوند.
- برای پیش‌نویس‌ها از یک Durable Object برای هر مدیر استفاده می‌شود، نه ساخت رکورد جدید KV برای هر پیام گفتگو. یک هماهنگ‌کننده انتشار درخواست‌های ربات را ترتیبی انجام می‌دهد.

## مرز اتوماسیون

در این نسخه ادمین فایل یا فوروارد آن را **در گفتگوی خصوصی ربات سوم** می‌فرستد. ربات پست‌های دلخواه کانال را خودکار به اثر حدسی متصل نمی‌کند؛ خواندن تاریخچه کانال یا پایش مستقیم همه کانال‌ها اضافه نشده است. نوع زیرنویس از نام فایل قابل اعتماد نیست.

برای جلوگیری از انتشار ناخواسته پیش‌نویس‌ها، وقتی `CONTENT_BOT_SECRET` در سایت تنظیم باشد، مسیر قدیمی واردکردن خودکار پست‌های **مخزن فعلی** از ثبت مستقل آن‌ها صرف‌نظر می‌کند. این تغییر عمدی است: انتشار از این مخزن از مسیر تأیید ربات سوم انجام می‌شود. واردسازی سایر کانال‌ها رفتار قبلی را دارد. ربات‌های قدیمی webhook خودشان را حفظ می‌کنند.

## استقرار

۱. یک ربات جدید در BotFather بسازید. توکن را در چت، Git، فایل تنظیمات یا اسکرین‌شات عمومی نگذارید.

۲. در Worker اصلی سایت، این تنظیمات را اضافه کنید:

- Secret: `CONTENT_BOT_SECRET`، یک مقدار تصادفی حداقل ۳۲ کاراکتر.
- Variable: `CONTENT_ADMIN_IDS`، شناسه عددی تلگرام مدیران، جداشده با ویرگول.
- کانال مخزن فعلی در تنظیمات سایت باید مقدار معتبر داشته باشد.

هر مدیر باید **هم در allowlist باشد و هم واقعاً نقش admin در حساب سایت داشته باشد**. برداشتن نقش admin دسترسی را قطع می‌کند. کلید مشترک به‌تنهایی جایگزین کنترل نقش نیست.

۳. فایل `worker.js` جدید را در Worker اصلی منتشر کنید. ساختار رکوردهای فیلم و کاربر حفظ می‌شود؛ مسیر خصوصی `/api/content-bot/*` اضافه شده است.

۴. `content-bot/wrangler.toml` را تنظیم کنید:

- `service = "film"` باید نام واقعی Worker سایت در همان حساب Cloudflare باشد (Service Binding، نه آدرس مرورگر).
- `SITE_PUBLIC_ORIGIN` دامنه‌ای است که لینک صفحه اثر از آن کپی می‌شود، بدون مسیر و بدون `/` انتهایی.
- `CONTENT_ADMIN_IDS` همان فهرست مدیران در سایت.
- Durable Object مبتنی بر SQLite به نام `EDITOR` و migration همراه فایل لازم است. این ربات را نمی‌توان فقط با paste کردن فایل در Worker معمولی، بدون binding و migration، کامل راه انداخت.

۵. از پوشه `content-bot` با Wrangler یا تنظیمات Secrets کلودفلر، این سه secret را تنظیم کنید:

```sh
npx wrangler secret put CONTENT_BOT_TOKEN
npx wrangler secret put CONTENT_WEBHOOK_SECRET
npx wrangler secret put CONTENT_BOT_SECRET
npx wrangler deploy
```

`CONTENT_BOT_SECRET` باید دقیقاً برابر مقدار سایت باشد. `CONTENT_WEBHOOK_SECRET` مقدار مستقل تصادفی ۳۲ تا ۲۵۶ کاراکتری از حروف/عدد/خط‌تیره/آندرلاین باشد. مقادیر واقعی در فایل TOML قرار نمی‌گیرند. Durable Objects و Service Bindings باید در حساب شما فعال/پشتیبانی شوند؛ هزینه و سهمیه جدا از KV را بررسی کنید.

۶. ربات سوم و ربات ارسال فعلی را مدیر مخزن کنید. ربات سوم برای کپی و حذف پیام‌های پیش‌نویس، اجازه ارسال و حذف پیام لازم دارد. حفاظت محتوا می‌تواند فوروارد/کپی را مسدود کند؛ در این صورت خود فایل را بفرستید یا دسترسی مجاز مخزن را اصلاح کنید.

۷. برای تنظیم webhook فقط ربات سوم، متغیرهای `CONTENT_BOT_TOKEN`، `CONTENT_WEBHOOK_SECRET` و `CONTENT_BOT_ORIGIN` (آدرس Worker جدید) را به‌صورت امن در محیط محلی تنظیم و سپس اجرا کنید:

```sh
node content-bot/setup-webhook.mjs
```

اسکریپت توکن را چاپ نمی‌کند و پیام‌های معوق را حذف نمی‌کند. روی ربات‌های ورود/ارسال اجرا نشود.

## نمونه گفتگو

```text
https://YOUR-SITE/#/item/i_123abc
[فایل Silo.S02E03.1080p.mkv با کپشن «نسخه بدون سانسور»]
/next
[فایل‌های هاردساب]
/next
[فایل‌های سافت‌ساب]
/review
/confirm
```

فرمان‌های دیگر:

- `/assign 2 3 1080`: اصلاح فایل منتظر به فصل ۲ قسمت ۳ کیفیت 1080؛ برای فیلم `/assign 1 1 1080`.
- `/accept`: تأیید مقصد فایل با نام مبهم، فقط اگر کیفیت و فصل/قسمت معتبر باشند.
- `/skip`: کنارگذاشتن فایل منتظر.
- `/remove 2`: حذف فایل دوم پیش‌نویس از مخزن و پیش‌نویس.
- `/refresh`: دریافت مجدد اطلاعات اثر پس از ویرایش در سایت، سپس بررسی مجدد و تأیید.
- `/cancel`: حذف فایل‌های پیش‌نویس از مخزن و پایان گفتگو.

پیش‌نویس غیرفعال پس از ۲۴ ساعت لغو و فایل‌های آن پاک می‌شود؛ حذف پیام منوط به محدودیت‌های تلگرام و مجوز ربات است. تا وقتی نتیجه انتشار نامعلوم است، حذف/لغو و انقضا متوقف می‌شود تا فایل احتمالاً منتشرشده پاک نشود. در این حالت `/confirm` برای ادامه همان انتشار است؛ پس از لغو دسترسی مدیر ممکن است بررسی دستی لازم شود.

## ایمنی و محدودیت‌ها

- همه فایل‌ها قبل از نوشتن اثر اعتبارسنجی می‌شوند؛ نوع و کیفیت پیش‌فرض نامعلوم نداریم.
- مراحل حذف/ردکردن را با محتوای آزمایشی تست کنید. از پایگاه داده پشتیبان بگیرید.
- درج فایل‌ها شناسه ثابت دارد و رسید انتشار داخل همان رکورد اثر نگهداری می‌شود (آخرین ۱۶ رسید). retry معمولی پس از خطای شبکه نسخه اضافه تکراری نمی‌سازد و ایندکس‌های ناقص را ترمیم می‌کند.
- پیام‌های تکراری webhook در هر نشست با شناسه update کنترل می‌شوند. با این حال API تلگرام و ذخیره Durable Object تراکنش مشترک ندارند؛ قطع ناگهانی دقیقاً پس از کپی و قبل از ثبت نتیجه ممکن است پیام اضافی در مخزن باقی بگذارد. تضمین exactly-once ارائه نمی‌شود.
- انتشارهای ربات ترتیبی‌اند و تغییر نسخه اثر بررسی می‌شود، اما KV تراکنش/CAS ندارد: همزمان با تأیید ربات، همان اثر را در پنل یا مسیرهای دیگر ویرایش نکنید. شمارنده‌ها یا سایر مدیران روی KV همچنان محدودیت سازگاری نهایی دارند.
- تشخیص واقعی صوت یا وجود subtitle با تحلیل محتوای ویدئو انجام نمی‌شود؛ انتخاب مدیر ملاک است.
- رمزها، شماره‌ها، کلید امضای نشست و فایل‌های کامل کاربران وارد لاگ یا Git نشوند.

## تست

```sh
node tests/check.mjs
node tests/content-bot.mjs
node --check content-bot/worker.mjs
node --input-type=module --check < worker.js
```

تست‌های محلی با سرویس‌های ساختگی اجرا می‌شوند؛ صحت مجوز کانال و ارسال/حذف واقعی تلگرام باید در استقرار آزمایشی بررسی شود. هیچ webhook یا namespace واقعی توسط این تغییرات محلی تنظیم نشده است.
